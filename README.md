# Model-level Backdooring Bias Detection for Text-to-Image Diffusion Models

## Overview

This review artifact contains the detection framework used to identify
model-level backdooring bias in text-to-image diffusion models.

## Repository scope

Included are the exact Stage-I detector architecture, intrinsic and
reference-assisted feature extractors, Stage-II reference-dispersion
measurement and conservative benign verifier, train/test prompts, experiment
configuration schemas, model metadata, and metric-reproduction utilities.

Fine-tuned benign/backdoored diffusion checkpoints and dedicated batch
backdoor-training scripts are not redistributed. Full feature extraction
requires user-provided model checkpoints. Result CSVs are generated by the
pipeline and are not prerequisites bundled with the source release.

## Full detection pipeline

1. Generate architecture-matched features with `classify/generate_features.py`
   and `configs/feature_jobs.json`.
2. Train/predict the canonical block-channel detector in
   `classify/classifier/feature_ablation.py`.
3. Aggregate prompt probabilities with
   `classify/evaluation/model_aggregation.py`:
   `stage1_score = mean(backdoor_probability)` and
   `stage1_prediction = int(stage1_score > threshold)`.
4. For Stage-I positives only, compute decision-free Stage-II measurements with
   `stage2_reference_dispersion_measurement.py`, then the benign veto with
   `stage2_perturbation_response_verifier.py`.
5. Apply the one-way veto in `classify/evaluation/final_decision.py` and compute
   TP/TN/FP/FN, Accuracy, TPR, FPR, and F1 with `metrics.py`.

Stage-II can change suspicious to benign; it can never change a Stage-I benign
model to backdoor.

The JSON launch manifests use environment variables for machine-local model
locations. `MODEL_ID` is a path-safe output name; `TEST_MODEL_ID` is an
SD1.4/SD2 suspect checkpoint; `TEST_LORA_ID` is an SD3.5/FLUX suspect LoRA.
Reference variables follow the architecture-prefixed names visible in
`configs/feature_jobs.json`. The launcher reports every missing variable
before starting a subprocess. For example:

```bash
export MODEL_ID=my_sd2_model
export TEST_MODEL_ID=/models/my_sd2_model
export SD2_CLEAN_REFERENCE_ID=/models/clean_sd2
export SD2_BACKDOOR_REFERENCE_ID=/models/backdoor_sd2
export MODEL_ROOT=/models/fine_tuned
export BASE_MODEL_ROOT=/models/base
python classify/generate_features.py \
  --manifest configs/feature_jobs.json \
  --job reference_sd2_test
```

The historical files under `configs/model_splits/` preserve model membership
and ordering but contain no server paths. `${MODEL_ROOT}` resolves fine-tuned
models and LoRAs; `${BASE_MODEL_ROOT}` resolves public base-model directories.

## Feature extraction

| Paper group | Artifact |
|---|---|
| LFD | per-prompt, per-step hidden-block tensors |
| latent trajectory | cosine, latent norm, adjacent-update norm CSVs |
| reference latent discrepancy | suspect/reference latent statistics |
| image similarity | OpenCLIP, LPIPS, MSE, SSIM, and HOG statistics |
| activation difference | flattened module-wise activation differences |

For parity with the confirmed paper run, OpenCLIP uses `ViT-L-14` without a
`pretrained` argument. The explicit `NONE_RANDOM_INITIALIZATION` sentinel in
the release preserves that historical call; changing it would change the
image-similarity features.

Architecture-aware detection uses the released `wo_cross` checkpoints for
SD1.4 and SD2 and the `full` checkpoints for SD3.5 and FLUX. The shared Stage-I
model threshold is 0.5.

## Prediction schema

Prompt prediction CSVs use:

```text
model_id,architecture,prompt_index,original_prompt,true_label,model_tag,
predicted_label,predicted_tag,backdoor_probability
```

`predicted_label` is diagnostic. Paper model aggregation uses the continuous
`backdoor_probability` only.

## Stage-II verification

The Stage-II verifier defaults to `tau_response=0.55`,
`tau_selectivity=0.14`, `min_valid_ratio=0.50`, and `min_domains=3`. Its six
prompt files are under `data/stage2/`, and perturbations use the banks embedded
in the measurement implementation.

## Paper experiments

- Architecture-aware variants are declared and validated.
- The supplied architecture-agnostic implementation, locked hyperparameters,
  and `architecture_agnostic_4.pt` checkpoint are included.
- Prompt sensitivity uses the supplied random-subset implementation: three
  seed-42 rounds generate nested N=10/20/50 subsets within ten groups. The
  per-file seed uses the prediction path relative to `predictions_dir`, so
  relocating the repository does not change the sample.
- Lightweight result records belong in `artifacts/paper_results/`; no result
  rows are synthesized.

## Environment setup

The paper environment used Python 3.10.20, PyTorch 2.7.1+cu118, CUDA Toolkit
11.8 (nvcc 11.8.89), cuDNN 9.1.0, and NVIDIA A40 GPUs. Create a clean Conda
environment from the repository root:

```bash
conda create -n backdoor-bias-detection python=3.10.20 -y
conda activate backdoor-bias-detection

pip install --index-url https://download.pytorch.org/whl/cu118 \
  torch==2.7.1+cu118 torchvision==0.22.1+cu118 torchaudio==2.7.1+cu118
pip install -r requirements.txt
```

Set `OPENCLIP_CACHE_DIR` to the OpenCLIP cache directory when running the
feature jobs. The paper configuration keeps the original explicit
`NONE_RANDOM_INITIALIZATION` setting described above.

Check the active runtime before generating features:

```bash
python --version
nvcc --version
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.backends.cudnn.version()); print(torch.cuda.is_available())"
```

The recorded run used seeded best-effort reproducibility, not bitwise GPU
determinism: cuDNN deterministic mode and PyTorch deterministic algorithms were
disabled. Exact versions of the direct runtime dependencies are pinned in
`requirements.txt`.
